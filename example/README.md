# Zotero → OCR → Obsidian Pipeline

Two scripts that automate a research workflow:

1. **`zotero_sync.py`** — Reads a Zotero SQLite database, discovers PDF attachments for citation keys listed in a sync file, runs each through the Chandra OCR server, and writes the results into `Raw Literature/<citationKey>/` inside an Obsidian vault.
2. **`create_slugs.py`** — Generates Obsidian note stubs from a BetterBibTeX CSL JSON export, keyed on citation keys that were previously OCR'd (as recorded in the zotero sync state file).

## Prerequisites

- A running Chandra OCR server (see `../ocr_docker/README.md`).
- A Zotero data directory (the folder containing `zotero.sqlite` and `storage/`).
- A BetterBibTeX sync file (see Zotero → BetterBibTeX → Sync settings).
- Python 3.10+ with dependencies installed:

```bash
pip install requests python-dotenv
```

## Configuration

Copy `.env.example` to `.env` and fill in the paths:

```bash
cp .env.example .env
```

| Env var                    | Required | Description                                                          |
|----------------------------|----------|----------------------------------------------------------------------|
| `ZOTERO_DIR`               | yes      | Path to the Zotero data directory (contains `zotero.sqlite`)         |
| `RAW_LITERATURE_DIR`       | yes      | Output directory for OCR results — one subfolder per citation key    |
| `ZOTERO_SYNC_FILE`         | yes      | JSON file listing which citation keys to process                     |
| `BASE_DIR`                 | no       | Base directory; used to derive defaults for other paths              |
| `NOTES_DIR`                | no       | Notes directory; derives `VAULT_DIR`, `STATE_FILE`, `SYNC_FILE`      |
| `VAULT_DIR`                | no       | Obsidian vault directory; derives `RAW_LITERATURE_DIR` default       |
| `OBSIDIAN_RESEARCH_DIR`    | no       | Output directory for `create_slugs.py`                               |
| `OCR_SERVER`               | no       | Base URL of the Chandra OCR server (default: `http://127.0.0.1:8080`)|
| `SLEEP_SECONDS`            | no       | Seconds to sleep between processing consecutive papers (default: 15) |

Any value not set in `.env` must be supplied on the command line.

## Running `zotero_sync.py`

```bash
python zotero_sync.py \
  --zotero-dir ~/.zotero/zotero.sqlite \
  --raw-literature-dir ./vault/Raw\ Literature \
  --zotero-sync-file ./zotero_sync.json \
  --state-file ./sync_state.json
```

Or relying on `.env` defaults:

```bash
python zotero_sync.py
```

The script tracks progress in a JSON state file so reruns are incremental — already-processed citation keys are skipped.

### Sync file formats

`zotero_sync.json` accepts any of:

```json
["key1", "key2", "key3"]
```

```json
[{"id": "key1", ...}, {"id": "key2", ...}]
```

```json
{"citationKeys": ["key1", "key2", "key3"]}
```

## Running `create_slugs.py`

```bash
python create_slugs.py \
  --sync-file ./zotero_sync.json \
  --state-file ./sync_state.json \
  --output-dir ./vault/Literature
```

Or relying on `.env` defaults:

```bash
python create_slugs.py
```

This reads the state file written by `zotero_sync.py` to determine which citation keys have been OCR'd, then generates a Markdown note stub for each one.

## Output structure

```
<RAW_LITERATURE_DIR>/
  key1/
    key1.md
    key1.html
    key1_metadata.json
    image_0.png, ...
  key2/
    ...

<OBSIDIAN_RESEARCH_DIR>/
  key1.md          # note stub generated by create_slugs.py
  key2.md
  ...
```
